# nebula-core-v3 Project State

Last updated: 2026-07-04

## Current Shape

`/Users/lali/Projects/reddit` is a multilingual YouTube story-entertainment pipeline for the ChonkerTalks channel network.

Current content strategy: the old "one language = one Reddit niche" plan has been replaced. The active plan is audience-first:

- One channel is defined by language, viewer promise, and tone.
- Shorts test fast hooks across region-specific entertainment topics.
- Long-form videos expand the winners into 8-18 minute explainers, story documentaries, moral-drama breakdowns, mystery timelines, or compilations.
- Reddit stories remain one useful source, not the whole strategy.
- `acc1` is configured as dark curiosity / strange facts for Russian-speaking viewers, not gaming. Its default `topic_mix` excludes `internet_lore`, `r/gaming` was removed from the channel subreddit list, and `topic_exclusions` block Minecraft/gaming-server topics before Gemini quality checks.
- The strongest priority markets are LATAM Spanish and Brazil Portuguese, followed by France, Germany, English, Italy, and opportunistic Russian-speaking/CIS diaspora coverage.

- `index.html`, `style.css`, `app.js` implement the local RedditSim recorder UI.
- `scraper.py` fetches candidate Reddit stories through PRAW OAuth2, weighted topic-family source planning, local duplicate/signature/similarity guards, channel `topic_exclusions`, velocity scoring, topic-fatigue penalties, and a bounded Gemini producer-quality gate, then writes `story_data.json` and `producer_queue.json`. The Gemini gate now works outside-in: it receives the market/channel audience job and a topic `content_bet` brief before scoring a Reddit post. It must decide whether the idea is worth pitching for the audience, then score first-screen hook, discussion potential, Shorts/long-form fit, novelty, character-voice fit, AI-slop risk, source/link dependency, duplicate risk, and legal risk before returning `PUBLISH | REWRITE | SKIP`. It also requires source-backed `hook_evidence`; the scraper ranks all approved candidates by producer score before picking the slot winner.
- `story_adapter.py` is the selected-story editorial layer. It calls the shared Gemini text provider after scraper selection and before metadata/translation, tightens the story without inventing facts, can move a source-backed hook into the opening, preserves URLs/timeline/point of view, and fails in strict mode when hook evidence is not found in the source title/body/comment text.
- `translator_tts.py` localizes non-English `story_data.json` through the shared Gemini text provider, keeps translated display fields for storyboard/card rendering, prepares separate narration-only fields where raw URLs are spoken as localized on-screen-link phrases and Russian numeric tokens are expanded into spoken words, then submits narration text to AI33 TTS v3. Channels can use separate `tts_voice` and `comment_tts_voice` roles; the script concatenates role segments into one `narration.mp3` and writes combined word timings for karaoke.
- `metadata_generator.py` generates YouTube packaging metadata through the shared Gemini text provider. It now treats tags as secondary, asks for three honest title/thumbnail/first-screen options, stores them in `packaging_options`, and writes the selected option into backward-compatible title/thumbnail fields.
- `thumbnail_generator.py` can generate a thumbnail image through VectorEngine image generation, but only with explicit `--confirm-spend`.
- `storyboard_generator.py` creates a deterministic no-API `storyboard.json` from `story_data.json`. It now emits `render_slides`: story text is split into screen-sized chunks, first story chunks show header/title but no footer when the story continues, middle story chunks show only continuation text, and only the final story chunk shows post upvotes/comments/share. In render mode, that final post footer is reserved in layout but hidden until the final karaoke phrase on the story slide; fallback slide-progress rendering reveals it only near the end of the slide. This applies to both vertical Shorts and horizontal long-form renders. Comment continuations follow the same rule for comment header/footer. Long stories advance by replacing the card content rather than scrolling, and short final orphan chunks are merged back when they fit.
- `render.py` opens the existing RedditSim UI in headless Chrome/Chromium, captures deterministic slide-progress or karaoke screenshots, and uses FFmpeg to render an MP4 from `storyboard.json`. In default `--orientation auto` mode, videos up to 180 seconds render vertical 9:16 (`1080x1920`, mobile layout), while videos longer than 180 seconds render horizontal 16:9 (`1920x1080`, desktop layout). Both orientations use the same in-text karaoke treatment; the horizontal render path fills the 16:9 viewport with a clean Reddit card and hides editor/sidebar widgets. If `narration.mp3` exists, it merges that file as an AAC audio track; if `narration.json` exists, it requires karaoke mode and passes the transcript to RedditSim for bright gold smart phrase highlighting directly inside the currently visible Reddit card text, including Russian spoken-number phrases mapped back to visible numeric tokens. Karaoke capture now samples phrase-change timestamps instead of only evenly spaced frames, so long videos do not skip visible highlight states, and final post metrics appear as the story-card ending rather than being visible throughout the slide. `--report render_report.json` writes render readback for the QA gate.
- `pre_publish_qa.py` is the fail-closed local/upload gate. It checks final MP4 audio/video streams, audio/video duration match, karaoke transcript coverage, render report state, story adaptation, hook evidence, narration URL sanitization, storyboard slides, metadata title length, and channel language before upload.
- `scripts/move-to-trash.sh` is the project safe-trash helper. Generated previews and scratch files must be moved to `Trash/<timestamp>/...`; agents must not use direct deletion commands.
- `uploader.py` is a YouTube Data API uploader with a fail-closed channel-token preflight against `channels.json` and post-upload metadata readback.
- `.github/workflows/auto_publish.yml` runs the cloud publish pipeline. It verifies the YouTube refresh token against `channels.json` before Reddit/Gemini/AI33/render work. The first full live smoke succeeded as an unlisted upload; the later OAuth/channel-mapping blocker is reported resolved by the user as of 2026-07-02, but the fail-closed preflight remains mandatory before any content-generation spend or upload.
- `.github/workflows/video_dry_run.yml` is currently a live manual workflow: it fetches Reddit content, can spend Gemini/AI33 quota or credits for quality/adaptation/metadata/localization/TTS, renders `final_output.mp4`, runs `pre_publish_qa.py`, and uploads story, producer queue, metadata, audio, transcript, render report, QA report, video, and previews. Manual dry-runs now support `topic_family`, `video_slot`, and `content_format`; use `content_format=shorts` to exercise live search/filtering while forcing a vertical artifact without YouTube upload.

## Current Pipeline Changes

- `translator_tts.py` now translates `title`, `body`, and each comment `body` for non-English channels before TTS. By default it overwrites `story_data.json` so downstream storyboard/render steps see localized text; use `--translated-story-output` to write a separate localized file.
- The default narration order mirrors visible card text for karaoke alignment: title, body, then comment bodies. For raw URLs and service link lines, visible fields keep the actual link on the card while `narration_title`, `narration_body`, and `comments[].narration_body` say the localized "link on screen" phrase. For Russian narration, visible numeric tokens stay unchanged in display fields while the narration-only fields spell numbers out for TTS, for example `6500+` -> `более чем шесть тысяч пятьсот` and `100%` -> `сто процентов`. `--include-comment-labels` can restore spoken "Comment by user" labels when strict word-level visual sync is not required.
- If `comment_tts_voice` differs from `tts_voice`, `translator_tts.py` now runs multi-voice TTS: title/body use the narrator voice, comment bodies use the comment voice, long text is chunked with `--tts-segment-max-chars`, FFmpeg concatenates the MP3 segments, and `narration.json` is rewritten with combined offset word timings when AI33 returns usable word timing data. The parser accepts explicit word timing arrays and ElevenLabs-style `alignment` / `normalized_alignment` character timing arrays, converting character timings into words for in-text karaoke. If AI33 returns audio but no usable timings, both multi-voice and single-voice paths generate `timing_status=estimated` word timings from exact narration text and MP3 duration so render-mode karaoke still highlights every visible word instead of failing or skipping words. Fully missing or partial unfillable timings still save sanitized payload-shape diagnostics, and `render.py` falls back to clean slide-progress frames with audio unless live `--require-karaoke` is active. Retryable AI33 task errors during per-segment multi-voice generation are retried before the pipeline fails.
- RedditSim karaoke highlights stable smart phrase groups instead of single words. Groups target 2-5 words and roughly 24-34 characters, stop at punctuation or line breaks, and never cross title/body/comment boundaries. Visible link tokens and Russian numeric tokens are single alias groups because they can correspond to multi-word narration placeholders. This matches short-video caption rhythm and makes estimated timings less visibly off. The `.kw-active` styling no longer changes font weight, padding, display mode, transform, line-height, or letter spacing, so highlighted words do not reflow neighboring text between lines. The render card body keeps its typed text span on the same HTML line as the `<p>` because `white-space: pre-wrap` would otherwise preserve source indentation as a visible first-line offset.
- `translator_tts.py --check-voice-config --require-voice-prefix elevenlabs_` validates narrator/comment voice ids without reading story text or calling AI33. `auto_publish.yml` runs this preflight before Reddit/Gemini/AI33 work.
- `translator_tts.py` now handles raw URLs and service link lines such as `Original thread: https://...` as narration-only substitutions. Storyboard/display fields keep the visible URL, while TTS reads localized phrases such as "el enlace está en pantalla" so videos show the link instead of printing the spoken placeholder.
- `storyboard_generator.py`, `app.js`, and `style.css` now render videos as centered slides rather than one long scrolling post. Story slides never include comments; comment slides show only comments; long story text is chunked into additional story slides. The final post footer is not visible while the final story slide is being read; it appears as the end-of-card metadata only on the final karaoke phrase, with layout space reserved so text does not jump. Render-mode font sizes were increased for Shorts and 16:9, and slide character limits were reduced so readability improves without overflowing the card.
